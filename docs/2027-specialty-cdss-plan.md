# 2027 年专科辅助诊疗 CDSS 建设规划

> 版本：v1.0  
> 编制时间：2026-11-11  
> 规划范围：2026 年第四季度至 2027 年 12 月  
> 专科范围：心血管内科、肺癌  
> 核心目标：完成从知识引擎到真实临床可用、可追溯、可取证的专科辅助诊疗闭环体系

---

## 1. 一页纸结论

本阶段项目定位为建设面向智慧医疗专科要求的 **专科辅助诊疗能力**。项目以现有知识引擎为基础，继续复用指南导入、知识图谱、规则引擎、审核工作流、医嘱套餐和诊疗路径等能力，重点补齐尚未实现的临床推荐服务、院内医嘱映射、医生工作站嵌入、反馈闭环、运行统计和评审取证能力。

2027 年底前聚焦两个专科：

1. **心血管内科**：作为首个闭环试点专科，优先选择 STEMI、心肌炎、肥厚型心肌病等已有较好知识资产的病种。
2. **肺癌**：作为第二个独立专科，覆盖筛查怀疑、诊断分期、基因检测、治疗方案、疗效评价、不良反应管理和随访，形成长周期诊疗路径示范。

专科辅助诊疗不是单一弹窗或规则提醒，而是围绕专科患者诊疗全过程提供结构化辅助：在诊断阶段帮助补齐评估依据，在治疗阶段给出候选方案和医嘱套餐，在监测阶段识别异常趋势，在出院和随访阶段生成管理建议。医生始终拥有知情、选择、修改和最终决定权。

---

## 2. 专科辅助诊疗的核心组成

专科辅助诊疗以专科知识包、患者上下文、诊疗路径和临床规则为基础，把推荐能力嵌入医生真实工作流。它覆盖诊断辅助、治疗辅助、监测辅助和随访辅助四类场景：

1. **诊断辅助**：根据症状、体征、检验检查、影像、病理和既往病史，提示待排除诊断、必查项目、评估量表和风险分层。
2. **治疗辅助**：根据诊断、分期分型、禁忌、肝肾功能、体能状态和路径阶段，输出候选治疗方案、医嘱套餐、理由和指南依据。
3. **监测辅助**：跟踪关键指标、药物不良反应、并发症风险和疗效评价节点，及时提示复查或干预。
4. **随访辅助**：形成出院后复查计划、症状预警、宣教、康复指导和长期管理建议。

医生工作站、电子病历和医嘱开单界面都是辅助诊疗的嵌入点。其中，医嘱开单场景用于把候选检查、检验、治疗和用药推荐转换为医生可编辑的医嘱草稿；其他场景则侧重提示、解释、留痕和闭环跟踪。CDSS 不直接替医生做决定，也不绕过医生开立医嘱。

```text
医生查看患者 / 进入诊疗节点
        ↓
CDSS 根据诊断、分期、检验检查、路径阶段生成辅助建议
        ↓
医生在工作站同屏查看建议、理由、指南依据和禁忌提示
        ↓
医生选择采纳、修改、拒绝或补充判断
        ↓
相关医嘱建议写入医生可编辑的医嘱草稿
        ↓
医嘱开立、审核、执行和结果回传
        ↓
系统记录反馈并触发再评估或随访建议
```

## 3. 年度目标

### 3.1 总体目标

到 2027 年 12 月，建成两个独立、可演示、可追溯、可运营的专科辅助诊疗体系：

1. 心血管内科完成 1-2 个病区真实试点，形成完整医嘱推荐闭环。
2. 肺癌完成独立知识包、诊疗路径、医嘱套餐和关键场景试点。
3. 推荐服务、反馈服务、运行日志、质量报表上线。
4. 知识包、规则、医嘱套餐、诊疗路径、评估量表统一版本化管理。
5. 完成专科相关评审材料、演示脚本、制度文档和运行数据准备。

## 5. 心血管内科建设方案

### 5.1 定位

心血管内科作为首个真实闭环专科，目标是验证平台能力、医生使用流程、HIS 集成方式和运营机制。该专科急诊场景清晰，医嘱可执行性强，适合作为 CDSS 从知识库走向临床流程的锚点。

### 5.2 优先病种

| 病种 | 优先级 | 理由 | 主要场景 |
|---|---|---|---|
| STEMI | P0 | 急危重症、路径清晰、已有图谱资产、评审演示价值高 | 急诊评估、再灌注、抗栓、监护、出院、随访 |
| 急性/暴发性心肌炎 | P1 | 已有病例和知识资产，可展示动态趋势和重症分层 | 诊断识别、重症监护、并发症监测 |
| 肥厚型心肌病 | P1 | 已有知识资产，适合展示分型、风险评估和长期管理 | 诊断分型、风险评估、治疗选择、随访 |
| 心衰或房颤 | P2 | 常见病、量表和风险分层成熟，适合扩展 | 评估量表、长期用药、复查和随访 |

### 5.3 需要补齐的能力

- 推荐服务：根据患者上下文、诊断、分期和路径阶段输出医嘱套餐。
- 工作站同屏推荐卡片：同屏展示推荐内容、理由、指南依据和禁忌提示。
- 医嘱草稿写入：推荐条目可进入医生可编辑的医嘱草稿。
- 安全核查：禁忌、剂量、重复检查、过敏、医生权限。
- 量表评估：GRACE、HAS-BLED、CHA₂DS₂-VASc 等。
- 高风险提醒：高危评估结果通知医生或护理站。
- 运行统计：推荐触发量、展示量、采纳量、修改量、拒绝原因。
- 医嘱闭环：开立、审核、执行、结果回传、再评估。

## 6. 肺癌建设方案

### 6.1 定位

肺癌作为第二个专科，用于验证专科复制能力和长周期诊疗管理能力。肺癌涉及影像、病理、基因检测、多学科治疗和长期随访，能够充分体现“专科全诊疗周期”的要求。

### 6.2 建设范围

2027 年肺癌不追求覆盖所有细分场景，优先完成非小细胞肺癌和小细胞肺癌的核心路径。

| 诊疗阶段 | 主要内容 |
|---|---|
| 筛查与怀疑 | 高危人群识别、影像检查、结节随访建议 |
| 诊断 | 病理确认、分型、分期检查、体能状态评估 |
| 分期分型 | TNM 分期、病理类型、驱动基因检测、PD-L1 表达 |
| 治疗决策 | 手术、化疗、放疗、靶向治疗、免疫治疗、多学科讨论 |
| 治疗监测 | 疗效评价、不良反应、血常规、肝肾功能、影像复查 |
| 出院与随访 | 复查计划、症状预警、宣教、康复和长期管理 |

### 6.3 需要补齐的能力

- 肺癌专科 Profile 和独立知识包。
- 肺癌实体词典：肿瘤部位、病理类型、TNM 分期、基因突变、治疗方案、化疗方案、靶向药、免疫治疗、不良反应。
- 术语映射：ICD-10、肿瘤形态学编码、手术操作编码、药品编码、检验 LOINC、院内本地码。
- 指南知识抽取：诊断、分期、检测、治疗、随访、禁忌和监测知识。
- 基因检测结果结构化：EGFR、ALK、ROS1、KRAS、MET、RET 等典型驱动基因。
- 治疗规则：根据病理类型、分期、基因状态、体能状态和禁忌生成候选方案。
- 医嘱套餐：评估套餐、分期检查套餐、治疗监测套餐、随访套餐。
- MDT 场景支持：至少能输出结构化 MDT 决策所需患者摘要和建议依据。
- 不良反应和随访提醒：骨髓抑制、肝肾功能异常、免疫相关不良反应等关键场景。

## 8. 系统建设内容

### 8.1 推荐服务

新增统一推荐接口：

```json
{
  "patient_ref": "patient-id",
  "specialty": "cardiology",
  "encounter_phase": "acute-treatment",
  "trigger_event": "diagnosis-updated",
  "context": {
    "diagnosis": ["STEMI"],
    "stage": [],
    "labs": [],
    "medications": [],
    "allergies": []
  }
}
```

输出应包含：

- 推荐医嘱套餐；
- 必选和可选医嘱条目；
- 推荐理由；
- 患者指标依据；
- 命中规则；
- 指南出处、章节和页码；
- 禁忌和安全提示；
- 可写入医生工作站的结构化医嘱草稿数据；
- 推荐有效期和状态。

### 8.2 临床工作站集成

临床工作站集成分为三步：

1. **只读展示阶段**：医生工作站侧栏展示推荐、理由和证据链。
2. **草稿写入阶段**：医生确认后，将推荐条目写入医生可编辑的医嘱草稿。
3. **闭环回传阶段**：回传医嘱状态、执行状态和结果事件，驱动后续推荐。

医嘱开单是其中一个集成点，不是专科辅助诊疗的全部。推荐服务还需要进入诊断评估、治疗决策、病情监测、MDT 讨论和随访管理等场景。医生始终拥有最终确认权，CDSS 不得绕过医生直接开立医嘱。

### 8.3 安全核查

推荐和开单前应执行：

- 禁忌核查；
- 过敏核查；
- 重复检验检查核查；
- 剂量上限核查；
- 肾功能、肝功能、体重、年龄等参数化调整；
- 药物相互作用；
- 医生权限和授权范围；
- 路径阶段适配性检查。

核查结果分为阻断、警示、提示三级，并全部写入日志。

### 8.4 数据接入

优先接入以下数据：

- 患者基本信息；
- 诊断和手术史；
- 过敏史；
- 用药记录；
- 检验结果和趋势；
- 检查报告；
- 病理结果；
- 基因检测；
- 医嘱状态；
- 护理评估；
- 随访记录。

实时决策优先使用临床数据服务或集成平台事件；科研历史数据仓库不作为唯一实时数据来源。

## 11. 关键风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| HIS 与电子病历厂商配合不足 | 最大交付风险 | 2026 Q4 冻结医生工作站集成接口契约，写入项目计划和商务范围；先采用侧栏展示降级方案 |
| 医嘱字典映射困难 | 推荐无法落地 | 信息科、药学、临床共同维护映射表，试点套餐优先 |
| 临床专家投入不足 | 知识质量不可控 | 固化审核排期，审核记录纳入项目例会 |
| LLM 抽取噪声 | 错误知识进入临床 | 所有抽取内容默认草稿，必须专家审核后启用 |
| 医生觉得打扰 | 采纳率低 | 只在关键触发点推荐，支持一键引用、修改和拒绝反馈 |
| 肺癌知识复杂 | 建设范围失控 | 2027 年限定非小细胞肺癌和小细胞肺癌核心路径，不做全瘤种扩展 |
| 数据质量不足 | 推荐依据不完整 | 先完成试点专病数据核查，缺数据时明确提示而非猜测 |

## 13. 年度验收口径

2027 年项目验收不以“规则数量”“图谱节点数量”作为核心标准，而以真实临床闭环为准：

```text
指南审核通过
        ↓
进入专科知识包
        ↓
患者上下文触发推荐
        ↓
医生在工作站同屏看到辅助建议
        ↓
医生确认 / 修改 / 拒绝并留痕
        ↓
医嘱建议写入医生草稿
        ↓
医嘱开立和执行
        ↓
结果回传
        ↓
触发再评估或随访建议
        ↓
形成统计和质量改进
```

只要这条链路在心血管内科和肺癌场景中跑通，并具备审计、溯源和运行数据，即视为 2027 年专科辅助诊疗阶段目标达成。
